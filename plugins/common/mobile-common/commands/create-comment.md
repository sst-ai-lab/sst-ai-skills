厳密なリンターに従ってコーディングを行っているので、コードの編集はしないでください

処理の内容が変わらなくとも、記述された順番や表現を変えてはいけません

既存のコメントを編集してもよいですが、新規追加するコメントと内容が重複したり、矛盾が発生しないように注意してください

# Dartのコメントルール

## 概要
Dartコードにコメントを追加する際のルールを定義します。
これにより、コードの可読性と保守性を向上させます。

## コメントフォーマットルール
コメントは日本語で記述します。
文章の末尾は句点（。）（！）（？）などで終わらせます。
クラス名・メソッド名・変数名等の識別子を参照するには、ドキュメントコメント内でバッククォート `` を使用します。
このルールは、シングルラインコメント、マルチラインコメント、ドキュメントコメントのすべてに適用されます。
```Dart
/// 条件が満たされない場合は`StateError`をスローします。
///
/// `anotherMethod()`と似ていますが、動作が異なります。
```

特定のクラスのメンバーにリンクするには、クラス名とメンバー名をドットで区切ります。
```Dart
/// `Duration.inDays`と似ていますが、分数日を処理します。
```

## コメントの種類と使い分けのルール

1. **シングルラインコメント**
    `//` を使用し、コードの特定の行に対する簡単な説明を追加します。
    for文に対して`// ループ`など、コードを読めば明らかなことへのコメントは避けます。
    - 例: `// 出力先ディレクトリの選択を表示しファイル保存先を指定する`
    解読が難しいコードや、補足説明が必要な箇所に追記します。

2. **マルチラインコメント**
    `/* ... */` を使用し、コードの一部を一時的に無効にする場合に追加します。
    - 例: 
      ```
      /*
      この部分のコードは一時的に無効化されています。
      後で再度有効化する予定です。
      */
      ```
      
3. **ドキュメントコメント**
    `///` を使用し、クラス、メソッド、プロパティの説明を提供する際に追加します。
    このコメント部分は、宣言にカーソルを合わせたときにIDEが表示する情報として使用されます。
    また、Dart docツールで検出し、ドキュメントの生成にも使用されます。
    - 例:   `/// ユーザーの名前を取得します。`  

## ドキュメントコメントの記載対象

ドキュメントコメントは二つに分けられます。
1. **ライブラリコメント**
    ライブラリ全体の説明を提供します。ライブラリの最初に配置します。
    DartにおけるライブラリはDartファイル単位です。
2. **メンバーコメント**
    クラス、メソッドや関数、プロパティや変数などの各メンバーに対する説明を提供します。

### ライブラリコメント

ライブラリコメントは各Dartファイルの最初に追加します。

ライブラリコメントの構成要素:

1. **タイトル**
    ライブラリの名前を簡潔に示します。
2. **改行**
    タイトルの後に改行を入れます。
3. **概要**
    ライブラリの目的とクラス・メソッドの機能を簡潔に説明します。
4. **用語の説明**
    ライブラリ内で使用される重要な用語や概念を説明します。初学者では理解が難しい用語の説明に特に注意します。
5. **注意事項**
    ライブラリの使用に関する重要な注意事項や制約を記載します。
6. **著作権情報**
    ライブラリの著作権情報（作成日、更新履歴、担当）を記載します。

```dart
/// ### システム専用入力欄ライブラリ
///
/// 管理者やシステムユーザー専用の入力欄を提供するライブラリです。
/// このライブラリは、通常のユーザーには表示されない特別な入力欄を提供します。
///
/// ### 概要
/// このライブラリは、システムユーザーや管理者が使用するための特別な入力欄を提供します。
/// これらの入力欄は、通常のユーザーには表示されず、特定の権限を持つユーザーのみがアクセスできます。
///
/// 提供されているクラス一覧は以下の通りです。
/// - `SystemInputField`: システム専用の入力欄を提供するクラス
/// - `MaskedInputField`: マスキング付きの入力欄を提供するクラス
///
/// 提供されているメソッド一覧は以下の通りです。
/// - `SystemInputField.onChanged`: 入力欄の値が変更されたときに呼び出されるコールバック
/// - `MaskedInputField.isSensitive`: マスキングを有効にするかどうかを指定するプロパティ
///
/// ### 用語の説明
/// - システムユーザー: 特定の権限を持つユーザー
/// - 管理者: システム全体を管理するユーザー
///
/// ### 注意事項
/// - このライブラリはシステムユーザー専用です。通常のユーザーには表示されません。
/// - セキュリティ上の理由から、マスキング付き入力欄は慎重に使用してください。
///
/// ### 著作権情報
/// - 作成日: 2024年6月
/// - 更新履歴: 2024年6月 - 初版作成
/// - 担当: 担当者名やチーム名
library;
```
### メンバーコメント

メンバーコメントは各クラス、メソッドや関数、プロパティや変数の直前に追加します。
パブリックメンバー(コンストラクタ含む)には、必ずドキュメントコメントを追加してください。
プライベートメンバーには、必要に応じてドキュメントコメントを追加してください。プライベートメンバーのドキュメントコメントは、コードの可読性を向上させるために使用されますが、必須ではありません。

メンバーコメントの構成要素:

1. **概要**
    メンバーの目的と機能を簡潔に説明します。
    概要でメンバーを十分説明できる場合は、他の要素は省略します。
    繰り返しの表現を避け、宣言自体から推測できない情報を提供します。
    もしそのような情報が一切ない場合は、ドキュメントコメント自体を省略します。
2. **改行**
    概要の後に改行を入れます。
3. **説明**
    複数の文で説明が必要な場合、概要の後に続けて記述します。
    説明は基本的に箇条書きを採用してください。箇条書きを採用する場合、1つのパラメータの説明は同じ段落にまとめてください。
    箇条書きにした際に可読性が落ちる場合は、箇条書きを使用しないでください。箇条書きを使用しない場合は一文ごとに改行を入れます。
4. **使用例**
    メンバーの使用方法を示す簡単なコード例を提供します。使用例は必ず記述してください。
    コード例はマークダウンのコードブロックで囲み、言語を指定します。

```dart
/// ユーザーの名前を取得します。
///
/// ユーザーが設定した名前を返します。
///
/// 名前が設定されていない場合は空文字列を返します。
///
/// 使用例:
///
/// ```dart
/// String getUserName() {
///   ...
/// }
/// ```
String getUserName() {
  ...
}
```

- クラスのコメント

そのクラスのインスタンスは何を表していてどんな役割を持つのかに焦点を当てます。
必要に応じて、以下の情報を含めます。説明は基本的に箇条書きを採用してください。箇条書きを採用する場合、1つのパラメータの説明は同じ段落にまとめてください。箇条書きにした際に可読性が落ちる場合は、箇条書きを使用しないでください。箇条書きを使用しない場合は一文ごとに改行を入れます。
1. **不変条件**
    クラスのインスタンスが常に満たすべき条件（メンバーの初期値など）
2. **用語の説明** 
    クラス内で使用される重要な用語や概念を説明します。
3. **文脈の提供**
    クラスがどのような状況で使用されるかを説明します。
4. **使用例**
    クラスの使用方法を示す簡単なコード例を提供します。使用例は必ず記述してください。
```dart
/// 改行されないテキストの一部分で、末尾にハードまたはソフト改行が含まれるチャンクを表します。
///
/// ...
class Chunk {
   ...
}

/// aとbのうち小さい方の値を返します。
///
/// ```dart
/// min(5, 3) == 3
/// ```
num min(num a, num b) => ...

```

- メソッド・関数のコメント

メソッドや関数がパラメータ・戻り値・例外を持つ場合は、セクションを分けてこれらを説明します。
説明は基本的に箇条書きを採用してください。箇条書きを採用する場合、1つのパラメータの説明は同じ段落にまとめてください。
箇条書きにした際に可読性が落ちる場合は、箇条書きを使用しないでください。箇条書きを使用しない場合は一文ごとに改行を入れます。
各セクションの見出し行と本文の間に改行を入れます。
1. **パラメータ**
    メソッドや関数の各パラメータを文章で説明します。
2. **戻り値**
    メソッドや関数の戻り値を文章で説明します。
3. **例外**
    メソッドや関数がスローする可能性のある例外を説明します。また、どのようなときに例外がスローされるかを記載します。
4. **使用例**
    メソッドや関数の使用方法を示す簡単なコード例を提供します。使用例は必ず記述してください。

```dart
/// `path`のファイルを削除します。
///
/// パラメータ:
///
/// - `path`は削除するファイルのパスです。
///
/// 戻り値:
///
/// - 削除に成功した場合は何も返しません。
/// 
/// 例外:
///
/// - ファイルが存在しない場合は`IOError`をスローします。
///
/// - ファイルが存在するが削除できない場合は`PermissionError`をスローします。
///
/// 使用例:
///
/// ```dart
/// delete('/path/to/file.txt');
/// ```
void delete(String path) {
  ...
}
```
メソッドや関数が外部状態を変更する副作用を持つ場合は、コードが何を行うかに焦点を当てます。

```dart
/// サーバーに接続し、クエリ結果を取得します。
Stream<QueryResult> fetchResults(Query query) => ...

/// ストップウォッチを開始します。すでに開始されている場合は何もしません。
void start() => ...
```
値を返すことが主目的なメソッドや関数の場合は、返される値が何を表すかに焦点を当てます。
ブール型の値を返す場合は、値が表す状態（～かどうか）に焦点を当てます。

```dart
/// このイテラブルの`index`番目の要素を、イテレーション順で返します。
E elementAt(int index);

/// このイテラブルが`element`と等しい要素を含むかどうかを示します。
bool contains(Object? element);
```

一行解説、改行、参照元メソッドの説明の順に記載します。

この時、参照元メソッドの説明は「詳細は[クラス名.メソッド名]を参照してください。」と記載します。

``` dart

///
/// 詳細は[StringValidator.isHalfWidthOnly]を参照してください。
```

- プロパティ・変数のコメント

非ブール型のプロパティや変数の場合は、変数が何を表すかに焦点を当てます。

```dart
/// 現在の曜日を表します。`0` は日曜日です。
int weekday;

/// ページ上のチェックされたボタンの数を表します。
int get checkedCount => ...
```

ブール型のプロパティや変数の場合は、変数が表す状態（～かどうか）に焦点を当てます。

```dart
/// モーダルが現在ユーザーに表示されているかどうかを示します。
bool isVisible;

/// モーダルがナビゲーションに対するユーザーの意図を確認する必要があるかどうかを示します。
bool get shouldConfirm => ...

/// モーダルのサイズ変更が現在のブラウザウィンドウのサイズ変更にも影響するかどうかを示します。
bool get canResize => ...
```

プロパティにゲッターとセッターがある場合、ゲッター側に両方の説明を記載します。
```dart
/// PHレベルを取得または設定します。
///
/// 0から14の範囲で、酸性から塩基性を表し、7が中性です。
int get phLevel => ...
set phLevel(int level) => ...
```

## 記法

アノテーションがあるとき、ドキュメントコメントはアノテーションの前に記載します。

マークダウンは使用可能ですが、過度に使用しないようにします。
マークダウンのコードブロックには、フェンス行 `///` を使用します。

フォーマットのためにHTMLは使用しないようにします。

コメントは簡潔さを優先させます。

一般的に明らかな場合を除いて、略語や頭字語は使用しないようにします。
